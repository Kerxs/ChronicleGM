# Chronicle GM

Windows 本地 AI TRPG 主持与内容创作工具。Tauri 2 + Rust core + React/TypeScript + SQLite。

## 下载与更新

- 在 [Releases](https://github.com/Kerxs/ChronicleGM/releases) 下载 `Chronicle GM_<版本>_x64-setup.exe` 安装（当前用户安装，不需要管理员权限）。需要 Windows 10/11 与 WebView2（Windows 11 自带）。
- 模型需要自己准备：本机的 llama-server / Ollama / LM Studio 等 OpenAI 兼容服务，或者在软件里添加云端服务。软件不下载、不安装模型。
- **自动更新**：软件启动后会检查 GitHub Releases 上的新版本（可以在「模型与性能 → 模型服务 → 关于」里关闭），有新版本时标题栏会提示。安装包必须通过签名校验才会安装；世界、战役与设置都在数据目录 `%LOCALAPPDATA%\ChronicleGM`，更新不会改动。

## 目录

| 路径 | 内容 |
|---|---|
| `crates/rules` | 骰子表达式、剧情条件 DSL、效果解析（纯程序判定，不依赖数据库与 AI） |
| `crates/core` | 数据模型、迁移、仓储、修订与撤销、变更集、搜索、导入导出、版本快照、战役状态 |
| `crates/core/migrations` | SQL 迁移脚本（`world/` 世界文件，`library/` 资料库） |
| `crates/llm` | OpenAI 兼容客户端（重试、流式、取消、脱敏）、本机服务自动识别、能力实测、GGUF 只读识别 |
| `crates/gen` | 生成管线：上下文组装、提示词模板（`prompts/`）、分段任务、输出解析与修正 → 待审变更集 |
| `src-tauri` | Tauri 外壳，只转发命令，不含业务逻辑；API Key 存 Windows 凭据管理器 |
| `ui` | React 界面；`ui/src/bindings` 由 ts-rs 从 Rust 生成，不要手改 |

## 界面

- 苹果风格的白蓝浅色主题：半透明毛玻璃侧栏（按冒险 / 创作 / 系统分组，带图标）、白色圆角卡片、系统蓝强调色、分段控件式页签。颜色都是 `ui/src/styles.css` 顶部的变量。
- **GM 玻璃球**（游戏页顶部）：用 [@samasante/liquid-glass](https://github.com/samasante/liquid-glass)（MIT）做的液态玻璃，边缘有折射与色散。
  - 待命：一颗玻璃球。
  - 构思：球里一条细弧旋转，下方显示回合进行到的阶段（后端 `gm-stage` 事件：理解你的行动 → 程序判定 → 组织叙述 → 人物回应）。
  - 讲述：像灵动岛一样展开成面板，逐字输出叙述；开着自动朗读时随朗读音量起伏。讲完收回，这段叙述落进剧情流（同一段文字不会同时出现两遍）。
  - 玻璃球单独占一行，展开时把剧情往下推，不遮挡任何内容。完整的折射效果需要 Chromium 内核（WebView2 满足）。

## 图片

- **节点图片**：世界树节点详情的「图片」页签，可以选文件、拖放或粘贴添加，支持大图查看、说明、封面和删除。图片存在世界文件里（世界库 v9），随备份、还原、导入导出一起保存。
- **AI 看图描述**：让视觉模型把图片写成一段设定描述，可以复制或追加到摘要；不会自动写入。
- **参考图片生成**：一句话生成世界、节点 AI 辅助、剧本生成大纲都可以附带最多 6 张参考图片（上传，或用节点上已有的图片）。结果照常进入审阅台。
- 需要模型服务通过「看图」测试（模型服务页「重新测试」）。实测本机 Ornith-35B + mmproj 可以看图，见 `docs/image-input-report.md`。

## AI 剧本生成

- 模型由用户自备。软件只识别 127.0.0.1 常见端口上的服务（llama-server、Ollama、LM Studio 等，Breeze TTS 会识别为语音服务）并实测能力，不下载、不安装、不启动。
- 分段生成：大纲 → 逐章展开 → 完善人物；另有"只重写选中条目"（锁定条目不会交给 AI）与"继续扩展（只新增）"。
- 每次生成是一个任务（`gen_jobs`）：失败或取消不改动世界，原始输出保留，可重试。成功的任务产出待审变更集，在审阅台逐条确认后才写入。
- 服务支持结构化输出时使用 JSON Schema；否则把 Schema 写进提示词，并在输出无法解析时请模型修正一次。
- 非本机服务必须先打开"允许发送世界与剧本内容"开关。
- 自定义提示词：在数据目录的 `prompts\` 中放同名 `.j2` 文件即可覆盖内置模板（模板版本号会随之变化，记录在任务中）。
- 重新生成前端类型：`cargo test export_bindings`。
- 真实模型联调：先启动服务，再设置 `CHRONICLE_LLM_URL` 运行 `cargo test -p chronicle-gen --test real_service -- --ignored --nocapture`。

## 世界树

- 层级结构存于 `nodes`（物化路径 + 分数索引排序键），按父节点懒加载；界面使用虚拟滚动，只渲染可见行。
- 一句话生成世界：生成宇宙背景、历史、地理、势力、种族、人物、文化、科技魔法、事件传说等分类及主要节点、世界规则与关系。世界规则默认是草稿，确认后可设为核心设定（AI 此后不能修改）。
- 任意节点可以"生成子节点"或"扩写 / 重写 / 补全空白"；生成前读取祖先链、已有子节点、相关节点与核心设定。锁定或核心设定的节点不会交给 AI 修改。
- 关系：内置 24 种类型（人物 / 势力 / 地理 / 事件），支持自定义类型与世界内时间段；关系图只渲染邻域（1–3 层，最多 300 个节点）。
- 一致性检查（只读）：同一时期的对立关系、人物死后 / 出生前参与事件、同类重名、悬空关系。
- 版本快照（回滚前自动备份）、导出 / 导入（新世界、跳过、覆盖、副本）、回收站。

## 剧情分支

- 剧情图是有向图（允许汇合与带条件的循环）：开场 / 场景 / 选择 / 事件 / 结局 / 自由行动节点；边带条件（规则 DSL，程序求值，检定由程序掷骰）与效果（任务、线索、物品、关系、标志、变量、实体状态、解锁节点）。
- 编辑器：React Flow 画布（拖动摆放、从节点边缘拖出分支），条件与效果用表单编辑，并显示"读作"文字。
- 检查：开场、可达性、死路、可到达的结局数、条件与效果引用不存在的任务/线索/物品/节点、无条件循环。
- 模拟：在内存状态上预演（检定可选掷骰 / 当作成功 / 当作失败），不写入任何数据；试玩：创建真实战役逐步推进，状态写入战役覆盖表，世界设定不变。
- 生成剧情图时，模型看到的是短编号（任务 Q、线索 C、物品 I、其他条目 S、人物 N、已有剧情节点 P），由程序换回真实 ID；也接受唯一的条目标题。换回后仍不存在或种类不对的引用在写入前移除并在审阅台提示，不会进入剧情图（实测模型抄写 26 位 ID 会抄错）。
- 检查面板可"AI 为全部死路生成后续"：每个死路节点各排一个生成任务（最多 10 个）。生成任务排队依次执行，不会同时向本地模型发多个请求。
- AI：根据剧本生成整张剧情图；为某个节点按玩家行动（或无行动时补充选择）生成新分支——只新增节点与从该节点出发的边，格式不对的条件与效果被移除并在审阅台提示。

## AI 主持（游戏）

每个回合：玩家输入 → 程序组装上下文（当前剧情节点、程序判定过的可选分支、状态、在场人物、战役记忆、相关设定）→ AI 提议（意图、检定、效果、剧情跳转、需要说话的 NPC、新人物/地点、要记住的事实）→ **程序执行** → 有判定结果时 AI 按实际结果重写叙述 → NPC 各自回应。

- 检定由程序掷骰（种子可复现）；技能修正与 NPC 态度由程序维护，AI 不能修改。
- 效果逐条校验：引用必须存在于本剧本或世界；不能修改核心设定；不能直接引入内容；整组在一个事务中执行。
- 剧情跳转只能选当前节点的出边，条件仍由程序判定；剧本外行动不会被强行拉回主线。
- 新人物/地点只进入本战役，同时生成待审变更集，确认后才成为世界正典；同名内容会被拒绝。
- NPC 只拿到自己的资料、自己的知识与记忆、玩家可见的场景，拿不到剧本真相、剧情节点的主持人信息和别人的秘密；态度变化每回合最多 ±2。
- 检定失败时，模型写在无条件效果里的"发现"类效果（揭示线索、获得物品、解锁节点）不生效。
- **GM 替 NPC 说话的处理**：叙述里能归属到在场 NPC 的直接引语（点名的、"他/她"指代的、或紧跟在描写该 NPC 之后的）会被删掉，改由该 NPC 代理亲自回答（NPC 代理有知识隔离）；主持人视角里会提示。
- 所有生成任务发给模型的 JSON schema 中，每个对象的字段都是必填（可填空值）；否则 llama.cpp 允许跳过，实测模型因此不写简介。展开或补全后简介仍为空时，取玩家可见描述的第一句代替并在审阅台提示。
- 发给模型的 JSON schema 保持代码中的字段顺序（先决定谁说话、最后写叙述），且顶层字段全部必填；模型仍把字段写进叙述或台词末尾时，程序截掉 JSON 尾巴并回收字段。
- 泄露检查：叙述或 NPC 台词中原样出现主持人信息时标出（只能发现照搬，不能发现改写，因此只提示不拦截）。
- 战役记忆：要记住的事实、会话摘要（生成草稿 → 用户确认后才进入 GM 上下文）、NPC 记忆。
- 模型服务路由：GM 主持、NPC 对话、会话摘要可以分别指定服务。

### 规模基准（实测）

`cargo run --release -p chronicle-gen --example bench_scale`：5 万节点 / 20 万关系，本机（Ryzen 9 7845HX）实测中位数：

| 操作 | 耗时 |
|---|---|
| 展开节点（约 100 个子节点） | 0.4 ms |
| 全文搜索（≥3 字） | 51 ms |
| 两字短词搜索（LIKE 回退） | 32 ms |
| 节点的全部关系 | 0.1 ms |
| 关系邻域图（2 层，≤150 节点） | 4 ms |
| 上下文组装（展开节点） | 95 ms |
| 一致性检查（全世界） | 1.2 s |
| 导出世界包（10.7 MB） | 1.9 s |

`cargo run --release -p chronicle-gm --example bench_campaign`：5 万节点 + 5000 回合（2.1 万条事件、1000 条事实、30 个 NPC 各 200 条记忆、50 份摘要），不调用模型：

| 操作 | 耗时 |
|---|---|
| GM 上下文组装（每回合） | 1.7 ms（加核心设定索引前 310 ms） |
| NPC 上下文组装（每个 NPC） | 0.1 ms |
| 战役状态 / 可走分支 / 中断回合检测 | < 0.1 ms |
| 完整性检查（全世界） | 0.9 s |
| 自动备份（96 MB） | 0.3 s |

## 数据位置

- 资料库：`%LOCALAPPDATA%\ChronicleGM\library.db`（世界索引、设置）
- 世界：`%LOCALAPPDATA%\ChronicleGM\worlds\<id>.cgw`（每个世界一个 SQLite 文件）
- 版本快照：`worlds\versions\<id>\`；自动备份：`backups\`
- 错误日志：`logs\chronicle.log`（超过 1 MB 轮换，保留 5 份；只记录程序错误，不记录剧本内容）
- 开发时可用环境变量 `CHRONICLE_DATA_DIR` 指定其他目录。

## 数据安全约定

- 所有写入经过 `World::write`：一个事务 = 一个 commit，每个实体的前后内容记入 `revisions`，可撤销与重做。
- AI 产出只能以**变更集**进入世界：试运行校验 → 用户逐条接受/修改/拒绝 → 事务写入。失败不留下任何修改。
- 锁定内容任何人都需先解锁才能修改；核心设定（`canon_level = core`）AI 不能修改或删除。
- 删除一律软删除（回收站），可恢复或撤销。
- 战役中的变化写入战役覆盖表，不修改世界正典；事件日志只能追加（数据库触发器保证）。
- 骰子与检定由程序掷出（ChaCha8，战役种子 + 流号），结果可复现。

## 调查、任务与 NPC 系统

- **调查板**（游戏页"调查"页签）：
  - 线索有三种来源：剧本中被揭示的线索、GM 记录的新发现（自动记入）、玩家自己的笔记。
  - 线索之间可以建立关联：支持、矛盾、相关。
  - 玩家写下自己的推理，引用证据，状态（还在考虑 / 我相信 / 我否定）**由玩家自己判断，程序不评判对错，允许错误推理**。
  - 程序会沿"支持"关联找出间接证据（证据链），并列出与证据链矛盾的线索。
  - GM 能看到玩家的推理，但提示词要求它不确认、不否认，也不替玩家把线索串起来、揭晓答案。
- **动态任务**（"任务"页签）：
  - 剧本任务可以设定前置条件、完成条件、失败条件（规则 DSL）、期限（开始后 N 回合，或开始后故事时间 N 小时），以及相关的人物、地点、线索；剧本编辑器里有对应的表单。
  - 每个回合结束时由程序判定：条件满足就自动开始、完成或失败，超过期限就失败，原因写进事件日志。
  - 剧情中出现新委托时 GM 可以新建任务，并记录任务变化。
  - 隐藏任务在开始之前玩家看不到。
- **世界时钟与 NPC 日程**（"人物"页签）：
  - 故事时间默认从第 1 天 08:00 开始，每回合推进 GM 估计的时长（默认 15 分钟，最多 12 小时）；也可以手动"等待"。
  - 人物资料里可以设置日程（每个时段在哪里、做什么，可以跨过午夜），世界树的人物编辑页有对应的表单。
  - 程序按时间计算每个 NPC 在哪里、在做什么。**在场与否由日程决定**：只有此刻在场景地点的 NPC 才会参与对话，已死亡的不会。
  - 玩家不在场时，NPC 也会按日程活动（每次活动变化记一条），全程由程序批量计算，不调用模型。
- **NPC 心理**：
  - 恐惧、愤怒、怀疑、压力、忠诚（对玩家的信任在人物关系里），每次变化都要写明原因并记进事件日志。
  - NPC 回应时会给出情绪变化，每项每回合最多 ±10，原因记录了玩家说的话；GM 也可以提议情绪变化。
  - 情绪强烈时会影响 NPC 的说话和行为（例如非常害怕时想逃、高度怀疑时不透露信息）。
  - 恐惧、愤怒、压力随时间逐渐平复。
- 以上数据都通过效果和事件日志写入，随时间线回溯恢复，参与重放校验与结局比较。

## 世界模拟

游戏页"世界"页签。全部由程序计算，**不调用模型**；同样的战役种子和世界内容得到同样的结果。

- **环境**：
  - 昼夜由时刻决定，季节由天数决定（每季默认 30 天，变量 `cal.days_per_season` 可以改）。
  - 天气按季节的概率表决定，一天分四段，每段有可能转成相邻的天气。主持人可以在"世界"页签指定今天的天气。
  - 环境写进变量 `env.day`、`env.season`、`env.daypart`、`env.weather`，任务和触发器的条件可以引用。
  - 夜晚和雨雪天让旅行变慢。暴雨、暴雪时，日程里标为"户外"的人物会待在家里（人物资料的"家"）。
- **地图与旅行**：
  - 世界树里的区域、国家、城市、地点构成地图。
  - 用"通往"关系（可以单向）、"接壤"关系连接地点，说明里写路程（例如"2小时""90分钟""1天""半天"）。没写时，道路按 2 小时算，接壤按 4 小时算；"地点"与它所在的城市之间按 15 分钟算（城市之间必须用关系连接，同一区域不等于相邻）。目的地要选具体的城市或地点。
  - 程序计算最短路线和耗时，每一段路按走到那里时的天气与昼夜计算。旅行途中，世界照常运转。
  - 地图有图形和列表两种显示：图形地图按道路自动布局，显示探索状态、当前位置、标记和统治者，点地点查看路线。
  - 地点有三种状态：已探索、未探索（听说过）、未知。
    - 玩家视角看不到未知地点。
    - 去过的地点和沿途经过的地点变为已探索。
    - 到达目的地后，相邻地点变为"听说过"。
  - 玩家可以给地点添加标记。
  - GM 可以通过 `travel_to` 让玩家出发，耗时由程序计算；通过 `places_heard` 让玩家听说某地。
- **势力**：
  - 势力资料里可以设定目标和初始实力（财富、军力、影响、稳定，0–100）。
  - 势力之间的战争、同盟、贸易用世界树的关系设定。
  - 时间每跨过一天，每个势力行动一次：
    - 发展；
    - 征兵（目标偏军事的势力）；
    - 贸易（增加财富，冬季收益较少）；
    - 作战（军力决定胜负，恶劣天气和冬季会暂停）；
    - 停战（战败一方军力崩溃时）；
    - 结盟（有共同的敌人时）；
    - 宣战（目标是扩张、军力强时）；
    - 政变（稳定过低时）。
  - 值得记录的事件进入"世界动态"。GM 只能把这些事件作为传闻告诉玩家；势力的数值是主持人信息。
  - 领土：地点的统治者用世界树的"统治"关系设定；一方停战求和时，胜方占领败方的一个地点（优先与胜方领土相连的），变化只记在战役里。
  - 对人物的影响：本势力被宣战、战败、政变、失去领土时，成员（"隶属""领导""效忠"该势力的人物）的恐惧与压力上升；住在易主地点的人也会不安；开战时交战双方成员之间已有的关系变差。
  - 人物死亡时（不论来自战斗、GM 还是手动修改），和他关系好的人悲伤愤怒，和他敌对的人松一口气。
- **事件驱动**：
  - 剧本里的"触发器"和"关键事件"可以设置自动触发条件和效果，剧本编辑器里有表单。
  - 时间推进时，程序检查这些条件，满足就执行效果，并记入世界动态。默认只触发一次。
- **批量推进**：
  - 每次推进时间只按天批量计算，长时间跳跃最多模拟 365 天。
  - 实测（调试版本）：20 个势力推进 100 天约 0.4 秒。
- 以上变化都通过效果写入事件日志，随时间线回溯恢复；时间线比较里有单独的"世界状态"分类。

## 战斗、物品与人物成长

游戏页的"角色"和"战斗"页签。**所有数值都由程序计算**，AI 只提出意图（开战、攻击谁、买什么、做什么），程序结算后再由 AI 按实际结果描述。

- **角色卡**：
  - 六项属性（力量、敏捷、体质、智力、感知、魅力，修正 = (属性 − 10) ÷ 2）、技能、等级、经验、生命、防御、状态、伤势。
  - 玩家用 `party`，NPC 的初始数值写在人物资料的"战斗数值"（世界树里有表单）；战役中的变化记在战役里，不改动世界树。
  - 检定修正 = 技能 + 对应属性修正 + 装备加成 + 状态修正 − 伤势惩罚。剧情条件里的检定也用这个数。
- **成长**：
  - 升级所需经验按规则里的经验曲线计算。升级时由程序加生命上限、技能点，按设定的间隔加属性点。
  - 玩家在角色页分配点数。GM 可以给经验和金钱，单次有上限。
  - 玩家和 NPC 的每一次变化（经验、升级、加点、伤势、痊愈、制作、使用物品）都记进成长记录。
- **伤势和状态**：
  - 战斗中倒下记"重伤"（3 天），被暴击记"重创"（1 天），影响检定。
  - 状态可以每轮造成伤害（如中毒）、修正攻击与防御、跳过回合，按轮数或故事时间到期。
  - 时间流逝时每小时自然恢复生命，到期的伤势会痊愈。
- **物品**：
  - 世界树物品和剧本物品都可以设置价值（铜币）、稀有度、装备栏位（武器、护甲、盾牌、饰品）、伤害、射程、护甲、加成、使用后恢复、解除状态、命中附带状态、制作配方，编辑页有表单，保存时校验。
  - 背包里每件物品都记录来源：购买、制作、战利品、剧情。
  - 拿到武器或护甲时，如果对应栏位是空的会自动装备。
- **货币与交易**：
  - 金钱是受保护变量（GM 不能直接改），按规则里的货币名称和进位显示，例如"1 金币 8 银币"。
  - 人物资料里可以设置"商店"：库存、加价倍率、收购比例、本钱。
  - 买卖由程序按价格结算：与商人关系好（信任高）最多打九折，商人的钱不够时不收购。
  - 商人 NPC 的上下文里有程序定的价格，报价与结算一致。
  - 商人每天补货（有数量的商品每天补 1 个，不超过设定数量），本钱每天恢复一部分。
  - 世界局势影响价格：商人所属势力在打仗时，武器、护甲、盾牌涨价 25%；冬季治疗用品涨价 15%。商店里会说明原因。
  - 以物易物：拿背包里的东西换商人的东西，差价按收购价与售价用钱补。
- **制作**：
  - 材料齐全时由程序检定。成功就消耗材料、得到物品；失败差 5 以上时材料损坏，否则材料还在。
  - 制作耗时会推进故事时间。
- **战斗**（回合制）：
  - 先攻：每个参战者掷 1d20 + 敏捷修正，从高到低行动。
  - 行动点：每回合恢复。攻击、移动、防御、使用物品、自定义行动各有消耗。
  - 战场是 10×6 的网格，距离斜走也算一格。近战射程 1，远程武器看射程。
  - 命中：1d20 + 攻击加值 ≥ 防御。自然骰达到暴击点数时伤害骰掷两次，自然 1 必定失手。
  - 敌人和同伴由程序控制，**不调用模型**：优先攻击射程内生命最少的对手；远程单位被贴身时会后退拉开距离；敌人生命降到四分之一时检定一次士气，失败就逃跑（逃走的敌人不给经验）。名字是弓手、法师之类的敌人是远程的。
  - 战场上有 3–5 个障碍物（按战役种子生成，可复现）：挡路；远程攻击时，挡在攻击路线上、紧挨目标的障碍物提供掩体（+2 防御）。
  - GM 开战时可以带上在场的友好人物作为同伴（`combat_allies`）。
  - 临时敌人按等级生成数值；有战斗数值的 NPC 也可以参战。
  - 结束时生命和伤势写回角色卡。胜利后由程序发放经验和战利品。
  - 战斗页可以点格子移动、点敌人攻击。
  - 游戏中一个 GM 回合等于玩家一个完整的战斗回合：目标太远时程序先靠近再攻击，然后结束回合。
- **自定义规则**：
  - 每回合行动点、攻击和移动消耗、移动格数、暴击点数、经验曲线、每级生命和技能点、自然恢复、单次奖励上限、玩家倒下规则（倒地或死亡）、货币，都按战役保存，主持人视角里可以修改。
  - 可以添加自定义行动（攻击、治疗、施加状态，带骰子、属性、射程、状态）。
- **补充识别**：
  - 实测本地模型常常只在叙述里写"买下了""佩上了"，却没填对应字段。
  - 当玩家的话明确提到买卖、使用或装备物品、制作、动手，而方案里对应字段为空时，程序会再发一个很小的请求，只让模型从编号里选。
  - 不会每个回合都请求。
- 以上全部通过效果写入事件日志，随时间线回溯恢复；时间线比较里有"人物与战斗"分类。同样的种子和同样的行动，战斗过程相同。

## 剧情导演与 GM 控制台

游戏页的"控制台"页签，**只在主持人视角显示**。

- **剧情导演**：
  - 程序每回合记录紧张度和进展。紧张度来自战斗、玩家生命、任务期限、人物情绪、天气；进展包括揭示线索、任务变化、剧情推进、得到物品、到达新地点、战斗、GM 记下的新情报。
  - 连续多回合没有进展判为停滞（默认 4 回合），玩家几次行动几乎一样判为重复。
  - 程序会整理可用的剧情钩子：没揭示的线索、没开始的任务、没触发的触发器、可走的分支、没打过交道的人物、听说过没去的地方。
  - 停滞、重复或到了例行间隔时，回合结束后在后台以低优先级请导演分析（不阻塞 GM 回复），也可以手动请求。
  - 导演给出节奏判断（提高、保持、放缓）和 1–3 条建议：提示、麻烦、转折、人物主动行动、事件，并写明依据的事实。
- **导演只提建议，不修改任何数据**：
  - 主持人采用后，建议才作为主持人信息进入 GM 的上下文，并保留几回合。停滞时可以自动采用第一条，这个行为可以关掉。
  - GM 的提示词要求在合适时给玩家机会、玩家不接也没关系，**不强迫玩家选择**。
  - 叙述原样说出建议内容时，会被标为泄露。NPC 的上下文里没有导演的指引。
- **不擅自修改已确认设定**：
  - 提示词禁止改写核心正典和已确认的设定。
  - 涉及这些设定、又带有"其实、原来、并非"等改写意味的建议会标为需要主持人确认，不会被自动采用。
  - GM 执行任何效果时仍然经过原有的校验。
- **控制台内容**：
  - 当前场景：主持人信息、在场人物、分支及条件。
  - 世界状态和时间：环境与所有变量。
  - 人物：目标、秘密、情绪、关系、生命、此刻在做什么。
  - 隐藏剧情：核心设定、还没到达的剧情节点、隐藏任务。
  - 线索和所有触发条件：每个条件此刻是否满足、是否已经发生。
  - 剧情冲突提示：
    - 死亡人物仍被任务需要；
    - 剧情走进死胡同；
    - 玩家倒下；
    - 叙述泄露主持人信息；
    - 叙述与程序结算不符（例如结算没命中，叙述却写砍中）；
    - GM 的修改被拒绝；
    - 叙述里提到了还没揭示的线索却没有揭示（控制台的线索列表可以一键揭示）；
    - 叙述或台词里夹杂英文。
- **AI 决策与记忆检索记录**：每回合记录：
  - 上下文里各部分是否放入（放入、部分、省略）和用了多少 token；
  - 检索到的战役记忆（M 编号）和世界设定（W 编号）；
  - 采用中的导演建议；
  - 每个 NPC 回应时检索到的记忆；
  - GM 写明的决定依据（`based_on`，编号已换成原文）。
- **手动修改游戏状态**：
  - 用效果编辑器修改任何战役状态：变量、任务、线索、物品、关系、情绪等。
  - 必须写明原因。修改写入事件日志，可以回溯、参与重放校验，控制台里保留修改记录。

## 人物关系网络与世界知识图谱

- **人物关系网络**（"人物关系"页）：
  - 节点包括玩家、人物、势力（家族和组织都用势力表示）、种族；
  - 边分两种：世界设定中的关系（虚线），以及本战役中的动态关系（实线，越粗关系越深，绿色友好、红色敌对）；
  - 动态关系是有向的，**双方各自的看法分开记录**，包括强度、信任、好感、敌意，双向关系就是双方都有看法；
  - 支持拖动、缩放、搜索（带出直接关系对象）、按关系类型和强度筛选、自动布局（力导向）；
  - 点击人物查看档案和本战役中的全部关系；点击关系查看双方的看法，以及**每一次变化的回合、原因、前后数值和当时玩家的行动**；
  - 世界关系在战役中被设为不成立时，显示为"已不成立"，世界设定本身不变；NPC 死亡、受伤等战役状态会标在节点上。
- **关系变化必须有来源事件**：关系只能通过 `adjust_bond` 效果改变，而且必须写明原因，每次变化都会记进事件日志。关系历史直接从事件日志读取，所以会随时间线回溯一起正确恢复，并参与重放校验和结局比较。
  - NPC 在对话中态度变化时，会自动记入"NPC 对玩家"的关系（原因写明是哪句话）；
  - GM 也可以提议关系变化，但每项每次最多 ±15，并由程序校验人物是否存在；
  - GM 的上下文里会显示在场人物当前对玩家的关系数值。
- **世界知识图谱**（"世界图谱"页）：
  - 无限画布，按需展开 / 收起世界树，可见节点之间的世界关系画成虚线；
  - 搜索时会自动展开到目标节点的路径并居中显示；
  - "检查冲突与重复"会把有问题的节点标出 ⚠；
  - 对选中的节点可以"AI 扩展子节点"，结果进入审阅台，确认后才写入正式世界。
- **两套系统相互跳转**：人物档案可以跳到世界树或世界图谱；世界图谱里的人物、势力、种族可以跳到关系网络。
- 剧本编辑器可以把世界中已有的人物加入剧本人物表。

## 剧情回溯与多时间线

- **检查点**：以下时刻会保存完整战役状态：战役开始、每个完成的回合、手动推进剧情、战役结束。状态包括：
  - 状态表的全部行；
  - 回合数、骰子种子与计数、当前剧情节点；
  - NPC 记忆和临时实体的条数；
  - 会话摘要。
  
  每个检查点带校验值，并记录写入时的程序版本。
- **回溯**：只有战役结束后才能回溯。选一个历史节点后，会生成一条新时间线（一个新战役）：复制当时的完整状态、在那之前的全部事件、NPC 记忆、临时人物、会话摘要和更早的检查点，全部换新 ID。原时间线只读取、不修改，不同时间线之间完全隔离。新时间线可以再结束、再回溯（形成多层分支）。
- **骰子**：默认恢复当时的种子和计数，新时间线接下来的掷骰与原时间线当时的结果完全相同；也可以选择换新种子。
- **校验**：
  - 从起点重放事件日志，逐个比对检查点（变量、任务、线索、物品、关系、实体状态、到访记录、解锁、走过的分支、当前节点、骰子计数）；
  - 校验值不符的检查点不能用于回溯；
  - 回溯完成时会自检一次：新时间线的状态必须与检查点完全一致，否则整次回溯撤销。
- **管理**：时间线可以重命名、归档，也能比较多条时间线的结局和最终状态（只看不同之处）。
- **升级前的战役**：结束时会补建一个"升级时"检查点，在那之前的位置无法回溯，界面会如实提示。

## 性能中心、任务调度与托管模式

- **统一 AI 任务调度**（`crates/runtime`）：每次模型请求先排队拿许可。优先级依次为：
  - P0 GM 回复
  - P1 NPC 对话
  - P2 语音
  - P3 分析
  - P4 记忆整理（会话摘要）
  - P5 生成（剧本、世界、剧情图）
- **前后台分开计数**：按模型服务分别计数，前台（P0–P2）和后台（P3–P5）各有各的并发上限，正在运行的后台请求不会占住 GM 回复的位置。
- **任务管理**：支持暂停、恢复、取消单个任务，也可以整体暂停后台；支持去重（同一目标的同类生成不会重复启动）、排队超时与运行超时；语音队列有长度上限。
- **后台让路**：可以重做的后台分析（剧情导演的自动分析）在 GM 或 NPC 请求到来时会被取消、之后重新排队，GM 回复不会和它同时占用模型服务。长时间的生成任务不会被打断。
- **"检测能力"也走调度中心**（前台 P1），不会和正在进行的 GM 回复抢模型。
- **三种性能模式**：
  - 节能 / 平衡：GM 回复期间不启动新的后台请求；
  - 性能：后台可以两个并发，并与 GM 回复同时进行；
  - 采样间隔和空闲释放时长也随模式变化。
- **资源监控**：
  - 采集 CPU、内存、数据磁盘，以及本程序和托管模型进程的内存、CPU、磁盘读写；
  - 显卡信息：NVIDIA 用 nvidia-smi；没有 nvidia-smi 时改用 Windows 的"GPU 适配器内存"性能计数器和注册表里的显存大小（不区分厂商，没有温度，每 10 秒读一次）；都读不到时会注明，不编造数据；
  - 可用内存低于 2 GB 时暂停 P4 及以下任务，低于 1 GB 时暂停 P3 及以下任务。
- **托管模式（可选）**：
  - 你自己填写程序路径和启动参数（可以直接粘贴 `.bat` 内容自动拆分），软件负责启动、等待健康检查、停止和重启；
  - 崩溃后自动重启，5 分钟内最多 3 次；重启在单独的线程里进行，不耽误对其他托管模型的巡检，关闭应用时会中止；
  - 托管的模型崩溃重启期间收到的请求，会等它恢复后重试一次；
  - "给同一显卡上的其他模型预留显存"：设置后，参数里有 `--fit on` 且没有自己写 `--fit-target` 时自动加上 `--fit-target`（默认 0，不改动参数）。8 GB 显卡上同时托管语言模型和语音模型时建议设置（性能中心会提示，一键设置）。设置了预留的模型启动前，会先启动托管的语音模型，让显存按语音模型已在显卡上的情况分配，详见 `docs/fixes-report.md`；
  - 有请求时按需加载，空闲后自动释放；
  - 互斥组里的模型不会同时运行：先等对方手上的请求做完，再把它换下；
  - 端口上已经有你自己启动的服务时，标记为"外部"，不接管、不停止；
  - 关闭应用时，会停止所有由本软件启动的模型进程；
  - 软件不下载模型，也不替你选择或更换模型。
- **显存估算**：根据启动参数和 GGUF 元数据，估算权重、KV 缓存和计算缓冲的大小。这是估算值，实际占用以资源监控为准。
- **数据库探针与图谱渲染耗时**：数据库耗时在性能中心按需测量；剧情图和关系图的渲染耗时由界面实测后上报。

## 语音朗读

- 在「模型服务」里添加语音服务（例如 Breeze TTS，自动识别会找到 8137 端口上的服务），把「语音朗读」路由到它；或者直接在性能中心把它设为托管模型（不用另外添加服务），朗读时自动启动。
- 游戏页的叙述和人物台词旁边有 🔊；勾选"自动朗读"后，每回合结束自动依次朗读叙述和台词，可以随时停止。
- 声音：旁白的声音在设置页填写描述；每个人物的声音在世界树的人物编辑页填写，没有填时按身份和性格生成描述，并按人物固定随机种子，同一个人每次的声音尽量一致。
- 台词里括号中的动作描写（"（压低声音）"）不会被读出来。
- 请求走调度中心的语音优先级（P2）：同样的内容只合成一次，排队最多 16 条，不会无限堆积；托管的语音模型按需启动。
- 缓存：按"文字 + 声音"缓存 WAV，超过 500 MB 时删除最久没用的；设置页可以试听、清空缓存，性能中心显示队列与缓存。

## 战役档案馆

侧栏「战役档案馆」：同一个世界里的全部战役与回溯出的时间线（按"族"排列，子时间线缩进），可按名称、剧本、结局和状态筛选。所有统计都从只追加的事件日志现算，不另存结果，所以永远与存档一致。

- **统计**：回合、玩家行动、掷骰、游玩时长；玩家选择（每次剧情跳转从哪里、选了哪条路、当时是几选一）、剧情分支点、到过的剧情节点、结局数；NPC 存活与死亡（含死亡回合）；关系变化（每对人物的次数、类型变化、强度/信任/好感/敌意的净变化）；任务完成情况；线索；战斗结果（胜利/失败/撤退、轮数、敌人数、战利品）。
- **结局分布**：同一剧本所有时间线达到的结局与次数，以及还没有任何时间线达到的结局。
- **编年史**：按事件日志确定性生成（不调用模型，存档不变结果就不变）：玩家行动、进入场景、线索与任务进展、死亡、关系类型变化、战斗、回溯、结局；可保存为 Markdown。
- **章节**：可在当前位置"开始新章节"、改名、删除标记（只追加记录，不改变战役状态，回溯校验不受影响）；没有手动章节时按会话摘要分章，也没有摘要时按进入的剧情节点分章。
- **搜索**：在所有战役的玩家行动、叙述、NPC 发言、事实、章节、结局和会话摘要里搜索，可按类型和战役筛选（模型原始输出、上下文追踪等内部记录不参与）。
- **战役 JSON 导入导出**：导出一个战役，或连同它回溯出的全部分支一起导出（文件带格式版本与校验值）。导入时全部换成新 ID、事件序号与检查点重新编号、父子关系与分叉位置一并换算，**不覆盖任何现有战役**；导入前自动备份，导入后逐条时间线重放校验，任何一步失败整体撤销。战役引用剧本里的节点，所以要导入到剧本所在的世界（或先导入那个世界）。
- **完整性检查**：逐条时间线重放事件并与检查点比对、检查点校验值、所用剧本 / 当前剧情节点 / 父时间线是否存在、事件回合是否超过战役回合。问题战役可到「备份与还原」从备份恢复。

## 备份、恢复与完整性

- **自动备份**：打开世界时，距上次自动备份超过一天就备份一次（`<世界>-auto-<时间>.cgw`），保留最近 10 份。轮换只删除自动备份，升级前、还原前、修复前的备份永远不会被自动删除。工具页可"立即备份"。
- **从备份还原**：先只读校验备份（版本号、`quick_check`、是否为世界文件），当前状态另存为还原前备份，然后替换并重新打开；版本快照列表保留。有生成任务运行时拒绝。
- **完整性检查**：SQLite 自检、外键、全文索引与原始数据是否一致、节点层级路径、排序键、孤儿节点、名称索引、变更集内容。
- **安全修复**：只重建可推导的数据（全文索引、路径、排序键、名称索引），父节点丢失的节点移到根级；修复前先备份。数据库文件本身损坏时不尝试修复，提示从备份还原。
- **崩溃恢复**：重启后，运行中的生成任务标记为"已中断，可重试"；GM 回合有开始/结束标记，程序意外退出留下的未完成回合会在游戏页提示（已执行的效果保留在日志里）。
- **模型进程不留孤儿**：托管的模型进程放在 Windows 作业对象里，本软件即使被任务管理器强行结束或崩溃，系统也会随即结束这些进程，不会继续占着端口和显存。
- **写事务立即加锁**：写事务一开始就取得写锁（IMMEDIATE），另一个程序同时打开存档时写入会等待而不是报"database is locked"。
- **启动失败**：资料库打不开时不闪退，界面显示原因、数据目录与日志位置，且不改动出错的文件。

## 启动参数、缩略图与游戏页图片

- 「模型服务」页的「模型启动参数」：托管模型的参数按分组可视化编辑，可以从 .bat 导入（会替换 bat 里 set 的变量），目录外的参数原样保留。大语言模型会显示内存面板：模型加载后的内存、提示词缓存上限、其他托管模型，与物理内存对比；放不下时可以一键调小 `--cache-ram`。实测 llama-server 默认的提示词缓存（8 GB）是长时间游玩时内存持续上涨的原因。
- 节点图片有缩略图（世界库 v10），显示在世界树、世界图谱、人物关系网络里。
- 游戏页：「此刻的画面」（所在地点与在场人物）、叙述里提到的配图设定，点开看图集。图片说明只在主持人视角显示。
- 详见 docs/launch-params-report.md。

## 云端服务

- 「模型服务 → 添加服务（云端或本机）」：语言模型、语音合成、生成图片都可以用云端 OpenAI 兼容接口，有常用服务商预设（OpenAI、Claude、DeepSeek、通义、Kimi、智谱、豆包、硅基流动、OpenRouter 等）。API Key 只保存在 Windows 凭据管理器里。
- 云端服务默认不允许发送内容，要逐个打开；生图服务的「重新测试」不生成图片，避免产生费用。
- 节点「图片」页签里可以用「AI 生成图片」：描述按设定预填（不含主持人隐藏内容），预览后确认才保存。详见 docs/cloud-report.md。

## 迁移方案

- 版本号存于 `PRAGMA user_version`；新迁移在 `db.rs` 的 `WORLD_MIGRATIONS` / `LIBRARY_MIGRATIONS` 末尾追加，SQL 放在 `migrations/`。
- 升级已有数据前自动 `VACUUM INTO` 备份到 `backups\`；每个迁移独立事务，失败回滚并保留备份。
- 数据库版本高于程序时拒绝打开，不做修改。
- 导出包带 `format_version`，旧格式在 `bundle::upgrade_bundle` 中逐级升级。


发布新版本（维护者）：

1. 修改 `Cargo.toml`（workspace）、`src-tauri/tauri.conf.json`、`package.json` 里的版本号。
2. 设置签名私钥的环境变量后打包，会同时生成安装包和 `.sig` 签名文件。私钥不在仓库里，丢失后已安装的软件就无法再收到更新，请妥善备份。
   - `TAURI_SIGNING_PRIVATE_KEY`：私钥文件路径
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：私钥密码
3. 生成 `latest.json`（版本、说明、签名、安装包下载地址），和安装包、签名一起上传到 GitHub Release `v<版本>`。软件读取的是 `releases/latest/download/latest.json`。
