# 反剧情纠正改革 · 完成报告

日期：2026-11-19。审查报告见 `docs/anti-railroad-review.md`。

## 做了什么

| 方案要求 | 实现 |
|---|---|
| 取消强制剧情推进 | 删除"停滞就必须让事情发生、给推进主线选项"的程序提示；导演默认不自动采用建议、只提示；默认偏好改为"玩家决定走向" |
| 自由行动规则（优先级最高） | `free_play.j2`：GM 规划、GM 叙述、导演三份提示词都放在最前面引用；NPC 提示词加了"不是推动剧情的工具" |
| 动态事件状态 | `core/src/events.rs`：8 种状态，终态不回退；必需的人物死亡 / 失踪、必需的物品被毁时自动失效；条件满足时变成可触发；旧存档自动补生成 |
| 因果驱动 | GM 新字段：`player_goal`（玩家目标）、`event_updates`（拒绝 / 绕过 / 改写 / 失效 / 完成 / 失败）、`destroy_items`（彻底毁掉的物品）；新条件 `alive` |
| 事实优先级 | 上下文分出「已确定的事实（不能被叙事改写）」「玩家当前的目标」「潜在事件（尚未发生，只是可能性）」；结束的任务、毁掉的物品不再列给模型 |
| 事实保护 | `validate.rs::check_facts`：结束的任务不能改回去、死者不能复活（`can_revive` 除外）、毁掉的物品不能再给 |
| NPC 独立 | 失踪的人物不在场；离开场景后，没有日程、但写明了住处的人物只在住处；NPC 知道玩家拒绝了什么、现在想做什么，不再一遍遍劝 |
| 剧情纠正检测 | `railcheck.rs`：程序先找疑点（复活、物品再现、再次派发拒绝过的委托、把未发生的事写成已发生、没有因果的巧合、无视玩家目标），交给模型结合因果复核，再重写 → 重新生成 → 记冲突；不回滚任何状态 |
| 界面 | 任务面板显示新状态；GM 控制台显示「剧情事件」（状态和原因）和玩家目标 |

## 测试

- **模拟测试**（`crates/gm/tests/anti_railroad.rs`）：方案的测试 A–F 各一个，加上剧情纠正检测的重写、放行各一个，共 8 个，全部通过。
- **真实模型**（本机 llama-server，DeepSeek-V4-Pro-Qwen3.5-9B Q4_K_S，关闭 MTP，32K 上下文）：`crates/gm/tests/real_freedom.rs`，示例世界「雾湾」。

### 第一轮暴露的问题（已修）

1. 玩家把备用灯芯石扔进海里后，叙述写"箱子里整整齐齐码放着好几块备用灯芯石"。程序没有给物品，但疑点检测要求叙述里出现"拿到、找到"之类的词，没抓到。
   - 修正：被毁的东西只要又在叙述里出现，就交给模型复核。
2. 玩家拒绝主线后，三个 NPC 每回合都在念叨灯塔。
   - 修正：NPC 上下文写明玩家不做的事和他现在的目标。
3. "我不用钥匙也不撬锁，用桌腿撞门"被纠正成「开锁」检定。
   - 修正：跳过"不撬锁"这类否定说法，新增"撞开 / 砸开 / 踹开 → 运动"。
4. 叙述里出现短编号「苏桦（N2）」。
   - 修正：叙述和选项在保存前把编号换成名字，并去掉「苏桦（苏桦）」这样的重复。
5. 事件已经是"已绕过"，模型又写一次同样的状态，被当成错误报出来。
   - 修正：同样的状态当作没有变化。

### 第二轮结果

| 测试 | 结果 |
|---|---|
| A 关键人物死亡 | 莫伦的死亡状态保留。叙述里他像在场一样出现时，检测确认后**重写了叙述**；状态没有回滚 |
| B 拒绝主线 | 拒绝被记为"已绕过"；之后 6 个回合 GM 都围绕"攒钱买船"回应。NPC 偶尔还会提一句灯塔，频率明显下降 |
| C 摧毁关键物品 | 备用灯芯石记为已摧毁；再去灯室翻找，没有凭空出现第二块 |
| D 非预设解决 | 镜子和油灯搭信号灯被接受并按规则处理（一次失败、一次部分奏效），没有被拉回"找灯芯石" |
| E 长时间偏离 | 不再出现"必须推进主线"的程序提示；GM 不主动把玩家带回灯塔 |
| F 连续改变 | 主线任务记为"被玩家改变"，原因写明；时间线校验通过 |

## 已知问题

- 9B 模型偶尔给 NPC 换身份（码头上的老水手被写成"莫伦"）。人物身份核对不在这次的范围内。
- 模型常编造不存在的线索编号（C1、C2），程序都拒绝了，只是控制台里噪音较多。
- 一个 NPC 的话里仍可能捎带一句主线（"不如想想怎么把灯芯石找回来"）。这是 NPC 按自己的立场说话，不再每回合都出现。
