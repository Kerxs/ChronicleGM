# 沉浸式互动与仪式系统 · 完成报告

日期：2026-11-19。范围：方案的 P0–P3 全部做完。

## 核心约束

- **AI 只能提出互动，不能宣布结果**：GM 在 `interaction` 字段提出，程序按场景对象、库存和规则校验，并生成可做的操作；成败由规则引擎结算。
  - AI 直接写效果宣布"门开了"会被拒绝（`campaign_records` 只有程序能写）。
- **互动选项不是限制**：输入框一直可用，玩家写别的办法时 GM 照常处理。
  - 自由行动检定成功时，用 `object_changes` 改对象状态（必须这一回合有检定，成败按检定）；同一对象上的互动卡片随之放弃。
- **全部持久化**：会话、对象状态、警戒都是战役记录，随检查点、分叉、读档一起保存；程序重启后待处理的互动还在。每一步都写事件日志。

## 统一互动引擎 `crates/core/src/interaction.rs`

- **请求字段**：`interaction_id / type / title / description / target / required_items / required_attributes / difficulty / available_actions / rules / possible_consequences / presentation / timeout_policy`。
- **场景对象**：写在地点节点 payload 的 `objects` 里（门、容器、机关、文件、尸体……），包括锁、内容物、线索、隐藏程度、机关、仪式。
  - GM 也可以提出场景里合理存在的临时对象，但不能凭空往里放物品或线索。
- **物品新字段**：`unlocks`（钥匙能开什么）、`uses_on`（能用在什么上）、`tags`（lockpick、bandage、tweezers、medkit、hacking、light、food、water……）。
- **结果交给叙述**：玩家操作完，结果作为"程序结算：玩家刚亲自完成的互动"交给下一回合的 GM，只交一次。

## 12 类互动

| 阶段 | 互动 | 怎么判定 |
|---|---|---|
| P0 | 骰子检定 | 本战役的检定规则（五级结果、优势劣势、骰池），可以亲手掷；难度按骰子换算（见下节）；3D 骰子用两颗 d10 演出 d100 |
| P0 | 钥匙与锁 | 钥匙要在身上（`unlocks` / `key_item`）；撬锁有小游戏（表现折算成 −3…+3 修正，成败仍由掷骰决定），大失败弄断工具、失败弄出声响；密码输错次数到了触发警报；电子锁可破解；可以强行破坏（动静大）或找备用入口 |
| P0 | 物品使用 | 用在自己、对象、人物或另一件物品上（另一件物品 = 组合），按物品设定判定 |
| P0 | 基础调查 | 普通 / 仔细（多花 30 分钟，+2）/ 用工具（优势）；可能发现线索、内容物、隐藏对象和通往未知地点的路；同样的检查第二遍没有新结果，不能刷骰 |
| P1 | 机关谜题 | 通用状态机，覆盖拉杆、齿轮、旋钮、压力板、图案、电路、多阶段、限步；GM 提出的谜题先用广度优先搜索确认可解 |
| P1 | 对话检定 | 说服、威胁、欺骗、贿赂、盘问、谈判、询问、利用交情；修正来自对方的态度、关系和情绪；对方怎么回应仍由 NPC 自己决定 |
| P1 | 物品组合 | 按配方和材料，走现有的制作流程 |
| P1 | 潜行与警戒 | 每个地点四级警戒：未察觉 / 怀疑 / 搜索 / 发现；观察、躲藏、制造声响、关监控、规划路线、潜行通过；随时间平息；被发现后按世界规则处理 |
| P2 | 战斗互动 | 瞄准部位（头 / 手臂 / 腿）、砸毁掩体、战场机关、投降，接在现有战斗系统上 |
| P2 | 地图探索 | 已有的图形地图、路线、旅行、标记，加上全屏查看；探索四周可能发现隐藏地点 |
| P2 | 医疗 | 急救、包扎止血、取出异物、解毒、稳住伤势；工具不对难度 +4 |
| P2 | 生存 | 规则开启生存时，食物和水随故事时间消耗；可以找食物、找水、吃、喝 |
| P3 | 限时 | 真实倒计时、故事时间、行动次数三种；只有 GM 写明紧迫原因时才启用，交涉和调查不限时 |
| P3 | 特殊剧情互动 | 材料仪式、精神抵抗（分轮）、梦境探索、能力发动（有消耗）、符号破解（研究可以得到提示）；由剧本声明，不绑定题材 |

## 难度换算（用户反馈：d100 和 d20 判定一样）

原来有两个问题：
- 剧本写了 1d100、检定方式却是「掷骰 + 修正 ≥ 难度」时，d100 和 d20 用同一条规则，GM 给的难度又是 d20 刻度（12、15），结果几乎必成功；
- 真正的百分骰规则里，目标值是"难度 + 修正"，而 GM 和互动卡片给的是 d20 刻度的难度（12 左右），结果几乎必失败。

现在：
- GM 和互动一律给**标准难度**（简单 8、普通 12、困难 15、极难 20），程序按本战役的骰子换算（`checks::scale`）：
  - 百分骰：按 d20 的成功概率换成百分比目标，例如难度 12、修正 +2 → 掷出 ≤ 55；
  - 2d6 等其他骰子：按均值和离散程度换算难度和修正，例如标准难度 12 → 2d6 的 8；
  - d20：不变。
- 主骰是 d100 时一律按百分骰规则判定（剧本生成、规则编辑器、旧战役都一样）。
- 检定说明里写明换算过程，例如"1d100 掷出 43，目标 ≤ 55（标准难度 12、修正 +2 换算成 55%）→ 成功"。
- 难度超过 30 的视为已经是本骰子上的数值（旧存档里写成百分比的目标），不再换算。

## 呈现方式

- **嵌入式**：对话流里的互动卡片。
- **局部操作区**：卡片里展开小游戏、密码输入、物品选择、机关状态、警戒表。
- **全屏**：战斗场景、全屏地图。
- **仪式演出层**：见下节。
- **场景互动条**（输入框上方）：这里能互动的东西，以及物品、组合、潜行、医疗、生存几个常用入口。

## 仪式演出

- 等级由程序按实际发生的事判定（`crates/gm/src/ritual.rs`），不靠 AI：
  - 序章、结局：四级，全屏演出加音乐；
  - 进入新地点、人物首次登场（有图片时显示肖像）、关键线索、重要物品、战斗开始、角色濒死、剧情转折：三级，转场卡片加专属音效；
  - 检定和普通操作：一级、二级，由骰子托盘和互动卡片负责。
- 声音全部由程序用 WebAudio 合成（`ui/src/lib/sfx.ts`），不带第三方素材：音效、背景乐（开场 / 探索 / 战斗 / 结局）、环境音（风、雨、城镇、洞穴、海）。
  - 数据目录 `audio/` 里放同名文件即可替换，设置里能打开这个文件夹。
- 设置 → 通用 →「演出与声音」：演出强度（完整 / 简化 / 关闭）、音效音量、音乐与环境音音量。省电模式降低特效，不减少玩法。
- 示例世界「雾湾」加了可互动的东西：灯室的铁门（撬锁、破坏，或从检修铁梯绕过去）、透镜转盘（三环机关）、守塔日志、潮洞的石台，以及藏着备用灯芯石的隐藏暗格。
- 教程新增一步，讲场景互动条。

### 真实模型（同上，示例世界）

- **第一、二轮发现并修好的问题**：
  - 模型把类型写成 "interaction"、目标写成不存在的编号 → 程序会规范类型，并检查有没有能互动的对象或玩家确实要做这类事，补渔网、打听消息不再变成互动。
  - 提出互动的同时又提了同样的检定，叙述先写出了结果 → 有互动时去掉重复的检定；叙述仍写了结果就删掉那几句。
  - `object_changes` 被模型写进了效果里 → 搬回正确的字段。
- **最终一轮**：开锁、调查、机关三次互动都按规则结算。开锁回合的叙述停在"双手抵住铁门"，没有提前写结果。玩家改用桌腿撞门时 GM 照常处理，叙述（没撞开）和对象状态（还锁着）一致。

## 已知问题与没做到的

- **联机**：联机界面还没有互动卡片，所以联机时 GM 不提出互动，改用检定。互动请求已经带了行动者，以后接上联机界面即可。
- **情绪语气**：NPC 音色沿用原来的设置，GM 用固定音色；按情绪调语速和音调要看 TTS 服务是否支持，这次没有做。
- **机关数据来源**：机关、仪式的数据要写在地点设定里，或由 GM 提出机关。剧本生成器还不会自动生成它们。
- **界面检查**：界面只在代码层面检查过（类型检查、单元测试），没有在真实窗口里逐个点过各种互动。这台电脑的屏幕之前一直锁着，截图是黑的。
