# 内置 llama.cpp 与模型管理系统：实施报告

方案和用户决定见 `docs/llama-review.md`。6 个阶段都做完了。代码都没有提交。

## 结构

```
crates/models/ (新)           不依赖 Tauri，各部分相互独立
├─ hw.rs           硬件检测
├─ net.rs          单文件下载
├─ runtime_mgr.rs  llama.cpp 运行环境
├─ repo/           模型仓库适配器（Hugging Face、魔搭）
├─ download.rs     下载任务管理器
├─ library.rs      模型库
└─ tune.rs         自动参数与运行状态
src-tauri/src/models.rs (新)  Tauri 命令薄层；耗时操作都放在后台线程
ui/src/pages/LocalModels.tsx  「模型与性能 → 本地模型」页
```

**各模块做什么**
- `hw.rs`：检测系统、架构、CPU 线程、内存、NVIDIA 显卡（显存、驱动、支持的最高 CUDA 版本）和 Vulkan。
- `net.rs`：单文件下载，支持 Range 断点续传、大小检查、SHA256 校验、进度回调和中止。
- `runtime_mgr.rs`：从官方 Releases 选构建，然后安装、自检、切换版本、回滚，并做损坏检测。
- `repo/`：独立的仓库适配器接口，下面分别是 Hugging Face 和魔搭的实现。
- `download.rs`：下载任务的持久化、断点续传、暂停 / 继续 / 取消、重试、并发上限、校验、去重。
- `library.rs`：模型库的添加、删除、默认模型、mmproj 关联、修改保存位置、完整性检查。
- `tune.rs`：自动参数、启动前兼容性检查、读取运行状态（`/metrics`、`/slots`）。

**推理服务**
- 进程管理直接复用已有的 `ModelManager`，没有另写一套。
- 系统用自动参数生成一份托管配置 `builtin-llm`，并把它登记成模型服务"内置模型"，地址是 `127.0.0.1:<端口>/v1`。
- 还没有默认路由时，它会被设为默认（以内置为主）。用户原来的路由不会被改动。
- 游戏照常经调度中心调用模型，用到时按需启动服务。

**数据位置**
- `数据目录/llama/`：
  - `runtimes/<版本>-<后端>/`：运行环境；
  - `runtime.json`：版本状态；
  - `downloads.json`：下载任务；
  - `library.json`：模型库记录；
  - `serve.json`：推理设置。
- 模型默认放在 `数据目录/models/`，可以改到别处。
- 更新和重装运行环境只动 `runtimes/`，不碰模型、配置和存档。

## 各阶段

| 阶段 | 内容 | 验证 |
|---|---|---|
| 1 运行环境 | 选构建、安装、版本管理、自动检查更新 | 模拟 Releases（下文第 1 点）；**真实**：用本机已有的 `D:\llama\llama-server.exe` 跑通自检，并检测本机硬件 |
| 2 仓库适配 | Hugging Face 与魔搭（下文第 2 点） | 模拟两家仓库的接口 |
| 3 下载管理 | 下文第 3 点 | 模拟服务器 |
| 4 模型库 | 下文第 4 点 | 单元测试 |
| 5 推理服务 | 自动参数和兼容性检查（下文第 5 点）；通过 ModelManager 启停；运行状态面板 | 参数推算的单元测试；**真实**：本机 9B 模型按自动参数启动 |
| 6 界面与游戏接入 | 五个子页：运行状态、模型库、模型市场、下载管理、运行环境；推荐默认模型一键下载；内置服务登记成模型服务并按需启动 | **真实端到端**：游戏请求触发按需启动，在示例世界跑两个 GM 回合 |

**1. 运行环境**
- 按硬件选构建：NVIDIA 显卡选驱动支持的最高 CUDA 构建，Windows 上会同时下载对应的 cudart 运行库；其次是 Vulkan，再次是 CPU（macOS 用 Metal）。不支持的构建（HIP、SYCL 等）会跳过，用户也可以手动指定后端。
- 安装流程：下载（断点续传；GitHub 提供 digest 时校验 SHA256）→ 解压到临时目录（防路径穿越）→ 把运行库汇总到 llama-server 所在目录 → 运行 `--version` 自检。自检通过才切换到新版本，任何一步失败都不影响正在用的版本。
- 保留上一个版本，可以回滚；更旧的版本自动清理。
- 损坏检测：文件丢失或自检失败时，状态显示为"损坏"，可以一键重装。
- 每天自动检查一次更新，只提示，不自动安装。
- 模拟测试覆盖：
  - 首次安装、更新、回滚；
  - 自检失败时不切换；
  - SHA256 不对时拒绝安装；
  - 删掉 llama-server 后检测出损坏，重装后恢复；
  - 只保留两个版本；
  - 更新不删除模型。

**2. 仓库适配**
- 两家都支持：GGUF 筛选、量化识别与筛选、分片模型整组选择、mmproj 推荐，以及大小、作者、许可证、更新时间、下载数。
- 私有仓库：
  - Hugging Face 用 Bearer 令牌；
  - 魔搭用官方 SDK 的登录接口，拿令牌换 Cookie。
- 模型卡只当纯文本显示：HTML 会被去掉，里面写的"指令"原样当文字显示，不执行。
- 魔搭官方 SDK 没有公开的关键词搜索接口。按"不依赖未公开接口"的要求，魔搭只支持按仓库 ID 或作者搜索，界面上写明了这一点。

**3. 下载管理**
- 实时速度、进度和剩余时间。
- 暂停 / 继续 / 取消，HTTP Range 断点续传。
- 任务持久化；程序关闭时没下完的任务，下次启动自动继续。
- 失败自动重试（指数退避，最多 5 次），之后可以手动重试。
- 并发上限可以设为 1–4 个。
- 检查文件大小；仓库提供校验值时校验 SHA256；做 GGUF 头检查。
- 文件先下到 `.incoming/`，全部校验通过后才移入模型库。
- 去重：同样的文件已经在下载就沿用原任务；模型库里已有就直接完成。
- 访问令牌不写进任务文件，也不出现在 URL 里。
- 模拟测试覆盖：
  - 暂停后确实不再下载；
  - 程序关闭再打开后续传，文件和原文件一致；
  - 服务器反复断开时自动重试；
  - 并发上限；
  - 校验值不对、下载到网页而不是 GGUF、服务器 500 → 重试到上限 → 修好后手动重试成功；
  - 取消后删除临时文件。

**4. 模型库**
- 添加已有 GGUF：不复制文件，读出模型信息。会拒绝 mmproj 文件和分片的非首片。
- 下载完成的模型自动加入，mmproj 自动关联。
- 设置默认模型。
- 完整性检查：文件丢失、大小变了、GGUF 结构损坏都能检出。
- 修改保存位置：模型目录里的文件搬到新位置，外部添加的文件不动。
- 删除：
  - 正在使用的模型不能删；
  - 删文件只删模型目录里的；
  - 分片模型连同其他分片一起删；
  - mmproj 只在没有别的模型使用时才删；
  - 界面上删文件要二次确认。

**5. 推理服务**
- 自动配置 GPU 层数、上下文、线程、批大小、KV 缓存类型、Flash Attention，以及显存 / 内存预算。
- 显存不够时依次退让：先把 KV 缓存改为 q8_0，再把上下文降到 8K，最后只把部分层放显卡。
- 内存明显不够时拒绝启动，并说明原因。
- 只监听 127.0.0.1，单槽位（`-np 1`），每一项参数都可以在界面上手动覆盖。

## 真实测试结果（不下载任何东西）

测试用的是本机已有的 llama.cpp build 12491（`D:\llama`），模型是 `DeepSeek-V4-Pro-Qwen3.5-9B-MTP-Q4_K_S.gguf`；硬件是 RTX 4070 Laptop 8 GB 显卡、32 GB 内存、24 线程。

- **自动参数**：34/34 层全部放显卡，上下文 8192，KV 缓存 q8_0，Flash Attention 开，12 线程。估计显存 5.9 GB。
- **直接启动**：加载约 3 秒（第一次冷启动 28 秒），生成约 51 tokens/s，读提示约 270–290 tokens/s，能读到上下文用量。
- **游戏端到端**：
  - 游戏请求经调度中心发出后，内置模型按需启动，加载 2.7 秒；
  - 两个 GM 回合分别用了 15–23 秒，叙述和 NPC 台词都正常；
  - 生成约 48 tokens/s；
  - 结束后进程全部停止，没有残留的 llama-server。
- **真实测试中发现并已修好的问题**：
  - 新版 NVIDIA 驱动的 nvidia-smi 表头改成了"CUDA UMD Version"，原来识别不出 CUDA 版本，现在两种写法都能识别；
  - 显存刚好够时，自动参数给出了自相矛盾的提示（"33/33 层放显卡，其余在内存"），现在会先重新判断能不能全部放下；
  - 新版 `/slots` 的上下文用量字段是 `n_prompt_tokens` 加 `n_decoded`，已经适配；
  - 默认 4 个并行槽位浪费显存，改成了 1 个。

## 兼容性

- 原来的托管模式（手填程序路径和参数）和外部服务都还能用，列在「模型服务」页。
- 内置模型的托管配置不存进资料库，由模型管理每次合并进去；和用户自己的托管配置冲突时（同一个 id 或端口），以内置的为准。
- 用户原来设置的默认路由不会被改。
- 单人和联机的存档格式都没有变。

## 已知限制 / 没有验证的部分

- **没有做真实下载**（按用户要求）：
  - GitHub Releases、Hugging Face、魔搭的真实接口都没有联网测过，只用模拟服务器验证了程序逻辑；接口字段是按各家公开文档和官方 SDK 写的；
  - 默认模型（Rocinante-X-12B Q4_K_M，约 7 GB）的一键下载也没有真实跑过。
- **界面还没有在真实桌面应用里点过一遍**，目前只通过了类型检查。
- 下载前不检查磁盘剩余空间；空间不够时，写盘失败会提示"空间不够？"。
- AMD 和 Intel 显卡查不到显存大小：默认全部放 GPU，启动失败时需要用户手动调低 GPU 层数。
- 从 GitHub、Hugging Face 下载在国内网络下可能很慢或连不上。目前没有内置镜像，要不要加镜像需要你决定。
