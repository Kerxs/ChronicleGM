## 已知问题和尚未完成的部分
1. **后台请求已经在跑时，GM 回复仍会变慢约 36%**（17 秒变成 23 秒）。调度中心保证 GM 不排队，但已经发出的后台请求无法中途暂停，模型服务会把算力分给两路请求。想让 GM 完全不受影响，可以选择"暂停所有后台任务"，或者等后台跑完。以后可以考虑"GM 请求到来时取消后台请求，之后重新排队"，但这会浪费已经生成的内容，所以这次没有默认这样做。
2. **GPU Offload 的"动态调整"**：只能在加载时由 llama-server 的 `--fit on` 根据当时的空闲显存自动适配（你的配置里有这个参数，已经实测可用）。软件提供"重启"操作来重新适配，互斥组会先释放其他模型的显存。llama-server 在运行中能不能修改 GPU 层数，我**没有验证**，所以没有实现。
3. **语音队列和缓存**：语音功能还没有接入。调度中心已经预留了 P2 优先级和队列上限，性能中心里如实显示"尚未接入"。
4. **显存数据只支持 NVIDIA**（通过 nvidia-smi），其他显卡会显示说明，不会编造数据。
5. **2 小时长时间运行**还没有测，计划在 Phase 8 做。本次联调持续约 5 分钟，资源采样一切正常。
6. 设置页里的"测试连接 / 检测能力"这类手动探测请求暂时不走调度中心。它们都是用户主动触发的一次性小请求。
7. 崩溃自动重启是在巡检线程里同步执行的。重启一个大模型的这段时间（实测 29 秒）里，其他托管进程的巡检会推迟。目前只托管了一个模型，影响不大；以后托管多个模型时会改成各自独立的线程。
