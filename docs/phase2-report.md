# Phase 2：剧情回溯与多时间线 · 完成报告

日期：2026-11-13。按任务书第五节实施。

## 设计
- **快照为准，重放校验**：
  - 战役开始、每个完成的回合、手动推进剧情、战役结束时，各保存一个**检查点**（完整战役状态）。
  - 回溯时以检查点为准恢复状态。
  - 事件日志用来复制历史，并通过**重放**核对检查点有没有出错。
- **回溯只能在战役结束后进行**。结束时会记录结局事件，并保存完整的最终快照。结束后的时间线拒绝任何推进（GM 回合、掷骰、效果、剧情推进都不行）。
- **每条时间线都是一个独立的战役**，所有数据按战役 ID 隔离。新时间线复制的内容全部换新 ID，原时间线只读取、不修改。

## 恢复范围（对照任务书的"必须恢复"）

| 项目 | 恢复方式 |
|---|---|
| 玩家状态、标志、变量 | 检查点里的 `state_vars` |
| NPC 状态 | `entity_overrides`（例如受伤、死亡） |
| NPC 记忆 | 复制当时已有的记忆。记忆只追加不修改，所以按写入顺序取前 N 条即可，逐条插入以保证顺序 |
| NPC 态度 | `attitude.*` 变量 |
| 人物关系 | `relation_overrides` |
| 任务和线索 | `quest_states`、`clue_reveals`（包括揭示时的回合） |
| 物品和装备 | `inventory` |
| 世界状态 | 实体覆盖、到访记录、解锁的节点、走过的分支、当前剧情节点 |
| 世界时间 | 回合数。目前项目里还没有日历时间，Phase 5 加入后会写进检查点 |
| 骰子记录和随机状态 | 复制掷骰事件；种子和计数恢复到当时，**新时间线之后的掷骰与原时间线当时的结果完全相同**（已测试）；也可以选择换新种子 |
| 历史事件 | 分叉点之前的全部事件按原顺序复制，再加一条"分叉"事件 |
| AI 记忆和上下文 | 要记住的事实（存在事件里）、会话摘要（覆盖范围换成新的事件序号）、临时人物和地点都会复制；GM 和 NPC 的上下文完全从这些数据重新生成 |

## 测试结果
- **Rust**：313 个通过，0 失败，4 个忽略（需要真实模型的联调）。
  - 新增时间线测试 5 个：
    - 完整状态恢复：上表每一项都逐项断言；原时间线回溯前后的"指纹"（状态、事件、记忆、检查点、事实、临时实体）完全相同；回溯后的骰子与原时间线一致。
    - 分支隔离与结局比较：两个分支各走一个结局，记忆互不出现，比较表能正确显示差异。
    - 连续回溯：三层时间线都通过校验。
    - 重命名、归档。
    - 篡改检测：直接改检查点会被校验值拦下，回溯拒绝使用；连校验值一起伪造会被重放比对发现；事件日志无法改写。
    - 升级前的战役：补建检查点并给出提示。
    - 200 回合时检查点的体积。
  - 新增 GM 层测试：回合自动保存检查点；结束后拒绝新回合；回溯后在新时间线继续玩时，GM 的提示词里**不包含**原时间线分叉之后的内容。
- **前端**：19 个通过（新增时间线树排序测试）。clippy 没有警告。发布版走查 14/14。

### 性能（5 万节点世界 + 5000 回合战役，每回合一个检查点）

| 项目 | 实测结果 |
|---|---|
| 检查点体积 | 5001 个，共 14.1 MB（平均约 3 KB） |
| 结束战役（含最终快照） | 1–2 ms |
| 重放校验 21001 条事件 / 5002 个检查点 | 181 ms，通过 |
| 从第 2500 回合回溯 | 169–288 ms |
| 再从新时间线回溯（连续回溯） | 12 ms |
| 回溯后组装 GM 上下文 | 1.65 ms |

第一次跑这个基准时校验没通过。原因是基准程序直接往日志里写了掷骰事件，却没有像真实掷骰那样增加骰子计数，重放校验正确地报出了"骰子计数不一致"。修正基准程序后通过。这说明校验确实能发现事件日志和状态之间的不一致。

## 已知问题和尚未完成的部分
1. **检查点里存了全部会话摘要的原文**：摘要越多，每个检查点越大。5000 回合、50 份摘要时平均约 3 KB，可以接受；如果以后摘要很多，可以改成只存摘要的数量和编号。
2. **世界时间、天气、势力、NPC 日程等还不存在**（Phase 4、5 才加入）。它们加入时必须同时写进检查点和重放规则，我会在对应阶段把它们纳入回溯测试。
3. **规则引擎以后修改后**，重放旧事件可能和当时的检查点对不上。检查点记录了程序版本，校验会把差异报告出来；回溯本身以检查点为准，不受影响。
4. **升级前就存在的战役**只能从补建的检查点开始回溯，界面会提示。
5. 自由沙盒模式（不使用剧本）下，模型有时会在"要记住的事实"里写出 C1、C2 这类编号（沙盒里并没有这些线索）。这不影响状态，属于模型的输出质量问题，以后可以在保存事实时把编号换成名称，或者把它过滤掉。
