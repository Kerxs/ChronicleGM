# Phase 3：人物关系网络与世界知识图谱 · 完成报告

日期：2026-11-13。按任务书第六节实施。

## 设计要点
- **关系变化必须有来源事件**：
  - 新增规则效果 `adjust_bond`（A 对 B 的看法按增量变化，原因必填），走现有的"效果 → 事件日志"通道。
  - 关系历史**直接从事件日志读取**，不另外存一份，所以它天然随时间线回溯恢复，并参与重放校验和结局比较。
  - 战役内的当前数值存在 `campaign_bonds` 表（世界库迁移 **v7**），并写进检查点。
- **双方各自的认知**：每个方向单独一行（A 对 B、B 对 A），各有关系类型、强度（0–100）、信任（0–100）、好感（−100–100）、敌意（0–100）。只有一方有看法时显示为单向，双方都有时为双向。
- **两套系统各自独立**：
  - 人物关系网络 = 世界设定中的人物 / 势力 / 种族关系 + 某个战役中的动态关系；
  - 世界知识图谱 = 世界树 + 全部世界关系；
  - 两者可以互相跳转，也都能跳到世界树编辑。

## 与 GM 的整合
- NPC 在对话中态度变化（每回合最多 ±2）时，自动写入"NPC 对玩家"的关系：好感 ±5 每级、信任 ±3 每级、敌意（态度变差时增加）、强度增加。原因写明是玩家的哪句话。
- GM 可以在方案里提议 `adjust_bond`。程序会检查双方是否存在、原因是否填写，并限制每项每次最多 ±15，超出就拒绝并说明。
- GM 的上下文里会显示在场人物对玩家当前的关系数值。
- 剧情图的条件和效果编辑器支持 `adjust_bond`；AI 生成剧情图时也能用短编号引用人物。

### 联调中发现并修复的问题
1. **搜索时把无关人物也带了进来**：战役关系没有按搜索结果过滤。已修复并补了测试。
2. **搜索或筛选后视图没有重新适配**：结果只剩几个节点时，它们缩在画面中央很小一块。现在数据变化后会自动适配；拖动节点不会触发重新适配。
3. **世界图谱搜索后没有定位到目标**：
   - 根本原因：某一层子节点超过 300 个（这次测试里根层级有 3001 个）时，目标的上级节点不在已加载的列表里。
   - 修复：现在会把路径上的节点补进去；坐标按布局结果计算，不依赖画面外节点的测量；并提示哪些层级被截断。
4. **300 个子节点排成一条很长的竖线**：改为分多列排列。
5. **关系历史的回合数少显示 1**：事件内部的回合从 0 开始计。已改成和其他页面一致。
6. **关系网络的连线绕出弯曲**：改为直线。

## 已知问题和尚未完成的部分
1. **关系类型是自由文本**：战役关系的类型由 GM 或编辑者填写，界面在能匹配时显示世界关系类型的中文名称，匹配不到就原样显示。
2. **NPC 之间的关系**：程序已经支持（GM 可以提议），但目前只有"NPC 对玩家"这一方向会在对话中自动产生；NPC 之间的关系要靠 GM 提议或剧情效果。Phase 4 加入 NPC 心理和日程时会扩展。
3. **"家族"没有单独的节点类型**，暂时用势力表示。需要的话可以在之后加一个节点类型（需要一次迁移）。
4. **世界图谱每层一次最多加载 300 个子节点**，超过的部分要靠搜索定位（界面会提示）。如果需要，可以之后加"加载更多"。
5. **人物关系网络默认最多 400 个节点**（加上关系对象最多再 200 个），超过时提示用搜索或筛选。
