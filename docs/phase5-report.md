# Phase 5：世界模拟 · 完成报告

日期：2026-11-13。按任务书 Phase 5 实施。

## 设计要点
- **全部由程序计算，不调用模型**：环境、旅行、势力行动、触发器都由程序计算；模型只负责把结果讲成故事。
- **事件驱动与批量推进**：
  - 只有在时间推进时（GM 回合结束、玩家等待、旅行）才进行模拟。
  - 势力按"跨过的天数"批量行动，每天一次。
  - 剧本触发器只在时间推进后检查一次。
  - 没有任何 NPC 或势力会持续调用模型。
- **可复现**：
  - 天气由战役种子、天数和季节决定。
  - 势力的随机数由种子、天数和势力名称决定（不用随机生成的 ID）。
  - 所以同一个世界、同一个种子，会得到同样的世界历史。
- **兼容现有系统**：
  - 新状态都写成 Phase 4 的战役记录（`place`、`marker`、`faction`、`world_event`、`trigger_fired`）或变量（`env.*`、`party.location`），全部经过"效果 → 事件日志"。
  - 因此新状态自动进入检查点，随时间线回溯恢复，参与重放校验和结局比较。
  - **没有新增数据库迁移**。

## 对照任务书

| 要求 | 实现 |
|---|---|
| 势力独立目标 | 势力资料的 `goals`。目标里的关键词影响行为：写"扩张、征服"的势力会宣战，写"军、防御"的会征兵 |
| 势力资源和行动计划 | 实力分四项：财富、军力、影响、稳定（0–100）。初始值写在势力资料的 `power` 里，世界树编辑页有表单，保存时校验范围。每天的行动：发展、征兵、贸易、作战、防守、停战、结盟、宣战、政变、因天气休整 |
| 战争、贸易、政变、冲突和联盟 | 战争、同盟、贸易沿用世界树的关系类型。作战由军力加随机数决定胜负；战败一方军力崩溃时停战。有共同敌人时可能结盟。目标是扩张、军力强时可能宣战。稳定过低时可能政变。贸易增加财富，冬季收益较少。这些变化都通过 `set_relation` 效果写入战役，**不改动世界树正典** |
| 玩家不在场时世界继续变化 | 跨过的每一天势力都会行动，值得记录的事情进入"世界动态"。GM 上下文里，这些事件标明"玩家只能通过传闻得知"，势力数值标为主持人信息 |
| 地点探索和地图标记 | 世界页签显示地图（按世界树层级排列），玩家可以添加或删除标记 |
| 已探索、未知、未探索 | 三种状态：已探索、未探索（听说过）、未知。<br>• 玩家视角不显示未知地点。<br>• 出发地、沿途、目的地及它们的上级地点都记为已探索。<br>• 目的地的相邻地点记为听说过。<br>• GM 可以用 `places_heard` 让玩家听说某地 |
| 旅行路线和时间消耗 | 用"通往"（可以单向）、"接壤"关系连接地点，说明里写路程（"2小时""90分钟""1天""半天"），也可以写在属性 `minutes` 里。<br>• 程序用最短路径计算路线，耗时乘以出发时的天气与昼夜倍率。<br>• GM 用 `travel_to` 让玩家出发，耗时由程序计算，不采用 GM 写的时间。<br>• 世界页签可以先查看路线，再出发。<br>• 途中世界照常运转 |
| 昼夜、天气和季节 | 昼夜（清晨、白天、黄昏、夜晚）由时刻决定。季节由天数决定，每季默认 30 天，可以通过变量修改。天气按季节的概率表决定（晴、多云、小雨、暴雨、雾、雪、暴雪），主持人可以指定当天的天气 |
| 环境影响 NPC、任务和事件 | • NPC：日程条目可以标为"户外"。暴雨、暴雪时，这类人物会待在家里（人物资料的 `home`），在场判定随之改变。NPC 的上下文里有时间、季节和天气。<br>• 任务和事件：环境写进变量 `env.day`、`env.season`、`env.daypart`、`env.weather`，任务条件和触发器条件都可以引用。<br>• 势力：恶劣天气和冬季会暂停作战。<br>• 旅行：夜晚和雨雪天让旅行变慢。<br>• GM：上下文里有环境说明，提示词要求叙述符合时刻、季节和天气 |
| 事件驱动和批量时间推进 | 剧本的"触发器""关键事件"可以设置自动触发条件 `when`、效果 `effects` 和是否只触发一次，剧本编辑器里有表单，保存时校验格式。长时间跳跃最多模拟 365 天；单次推进最多 7 天，超过 7 天的路程分段推进 |

### 联调中发现并修复的问题
1. **旅行时间算错（第 1 轮，程序问题）**：从酒馆到黑木镇只算了 45 分钟，正确的是 3 小时 15 分钟。
   - 原因：上下级地点之间都连了 15 分钟的"附近"边，同一区域的两座城市可以经过区域节点只隔 30 分钟。叙述里 NPC 说"走三个钟头"，程序却只扣了 45 分钟。
   - 修正：只有"地点"和它所在的城市之间算附近，城市之间必须用关系连接；目的地不能是区域或国家（提示选择具体的城市或地点）。已加回归测试。
2. **"听说"了自己所在的地方（第 1 轮）**：模型把灰石村、北境写进了 `places_heard`。现在已经知道的地点（包括所在地点及其上级）会被忽略，同一地点也不会重复记录。
3. **离开区域后，区域变回"未知"（第 2 轮）**：区域的已探索状态原来只来自"玩家在它里面"，没有记录下来。现在旅行时会一并记录出发地、沿途、目的地的上级地点。
4. **超过 7 天的路程只推进 7 天**（自查发现）：单次时间推进最多 7 天。现在长路程分段推进。
5. **势力测试偶尔失败**（自查发现）：随机数用了势力的 ID，而 ID 每次随机生成，所以同样的种子在不同世界里结果不同。现在改用势力名称，世界历史只由种子和内容决定。
6. **结盟永远不会发生**（测试发现）：结盟要求双方都处于战争中，但作战的判断排在结盟前面，处于战争中的势力每天都去作战。现在结盟排在作战之前。
7. **交战双方同一天各打一场**：现在同一对势力每天只打一场，另一方记为"防守"。
8. **GM 可以直接改位置或环境变量**（自查发现）：`party.location`、`env.*` 现在是受保护变量，GM 只能用 `travel_to` 改变位置，耗时由程序计算。

## 已知问题和尚未完成的部分
1. **模型偶尔用错字段**：
   - `places_heard` 里写了不太相关的地点（例如"农舍"），程序只做存在性和是否已知的检查。
   - 编造了不存在的线索编号（例如 C1、C2），被校验拒绝，没有影响数据。
   - 叙述里出现过一次英文单词（"daylight"）。
2. **势力推演是简单规则**：
   - 每天一个行动，数值是启发式的。
   - 还没有领土归属：战争不会让地点易主，也不会影响地点的状态或 NPC。
   - 势力不会主动和玩家互动。
   - 如果需要更复杂的势力 AI，可以在 Phase 7 的 AI 导演里加入。
3. **天气以天为单位**，一天内不会变化；旅行耗时只按出发时的环境计算。
4. **地图是树形列表，不是图形地图**：没有坐标，路线以文字显示。
5. **环境对 NPC 的影响目前只有两项**：户外改为待在家里，以及 NPC 上下文里的天气说明。NPC 之间的情绪与关系仍然不会因世界事件自动变化（Phase 4 的已知问题 5 只部分解决）。
6. **任务期限仍按回合计算**，还没有改为按故事时间（Phase 4 的已知问题 6）。现在可以用 `env.day` 写条件，例如 `fail_when: env.day ≥ 5`，间接实现按天的期限。
