# Phase 6：战斗、物品与人物成长 · 完成报告

日期：2026-11-13。按任务书第九节实施。

## 设计要点
- **所有数值由程序计算，AI 负责描述和互动**：
  - GM 方案里只写意图：开战（敌人名字、等级、数量）、这一回合的战斗行动、买卖、使用或装备、制作、奖励。
  - 命中、伤害、价格、经验、升级、制作成败全部由程序结算。
  - 结算结果交给 GM 重写叙述。
- **敌人和同伴由程序控制**：靠近最近的对手并攻击，不调用模型。所以参战人数增加不会增加模型请求。
- **兼容现有系统**：
  - 新状态都写成战役记录（`sheet`、`equip`、`combat`、`growth`、`item_source`、`shop_init`）、受保护变量（`money.*`、`rules.config`、`combat.active`），或沿用原有的战役物品表。
  - 全部经过"效果 → 事件日志"，所以随时间线回溯恢复，参与重放校验和结局比较。
  - 骰子用战役种子，同样的种子和同样的行动得到同样的战斗过程。
  - **没有新增数据库迁移**。
  - 原有的检定改为用角色卡计算修正，并兼容旧的 `skill.*` 变量。

## 对照任务书

| 要求 | 实现 |
|---|---|
| 回合制 | 按先攻顺序轮流行动。玩家的回合等待输入；其他参战者由程序依次行动，直到再次轮到玩家或战斗结束 |
| 先攻顺序 | 每人掷 1d20 + 敏捷修正（写入事件日志）。顺序显示在战斗页，并告诉 GM |
| 行动点 | 每回合按规则恢复（默认 3 点）。攻击 2 点、移动 1 点（最多 4 格）、防御 1 点、使用物品 1 点；自定义行动的消耗可以设置 |
| 伤害和状态效果 | 命中 = 1d20 + 攻击加值 ≥ 防御。自然骰达到暴击点数时伤害骰掷两次，自然 1 必定失手。武器可以附带命中状态（例如中毒每轮 1d2）。状态可以修正攻击与防御、跳过回合，按轮数或故事时间到期 |
| 战场位置 | 10×6 网格，距离按斜走也算一格；近战射程 1，远程看武器射程，超出射程不能攻击。战斗页点亮可以移动到的格子，红框标出可以攻击的敌人 |
| 自定义规则 | 每个战役单独设置：行动点、攻击与移动消耗、移动格数、暴击点数、经验曲线、每级生命和技能点、属性点间隔、自然恢复、单次奖励上限、玩家倒下规则（倒地或死亡）、货币名称与进位、技能对应属性；自定义行动（攻击、治疗、状态）。保存时校验 |
| 背包和装备 | 背包沿用战役物品表。装备分武器、护甲、盾牌、饰品四个栏位，影响攻击、伤害、射程、防御、检定加成。拿到装备时对应栏位空着就自动装备；战斗中换装备立即生效 |
| 货币和交易 | 金钱是受保护变量（GM 不能直接改），按"金币 / 银币 / 铜币"显示。商人设置库存、加价、收购比例和本钱；买卖在一个事务里完成：库存、双方的钱、物品来源都会更新。关系好最多打九折。GM 的奖励有上限 |
| 物品属性、稀有度和来源 | 价值、稀有度（普通 / 优秀 / 稀有 / 史诗 / 传说）、栏位、伤害、射程、护甲、加成、恢复、解除状态、命中状态、配方；编辑页有表单，保存时校验。每件物品记录来源（购买、制作、战利品、剧情、主持人给予） |
| 制作、购买和出售 | 制作：材料齐全时由程序检定；成功消耗材料得到物品，差 5 以上时材料损坏；耗时推进故事时间。买卖见上 |
| 属性、技能、经验 | 六项属性、技能等级、经验与等级。升级由程序计算：加生命上限、技能点，按间隔加属性点，每两级加攻击。玩家在角色页分配点数 |
| 伤势和状态 | 倒下记"重伤"（检定 −2，3 天），被暴击记"重创"（−1，1 天）。伤势影响检定与攻击。每小时自然恢复生命（战斗中不恢复），到期的伤势痊愈 |
| NPC 和玩家成长记录 | 经验、升级、加点、伤势、痊愈、制作、使用物品都写一条成长记录，玩家和 NPC 都有，角色页可以查看 |

### 真实联调（你的 llama-server，托管模式，共 8 轮）
场景：
- 酒馆里的铁匠兼商人：卖长剑 180 铜、治疗药水 60 铜。
- 玩家有 3 金币和 4 株止血草；止血药膏的配方需要 2 株止血草。
- 流程：问价 → 买剑和药水 → 佩剑 → 山路遇两只野狼 → 战斗 → 制作药膏。

第 1–7 轮暴露了问题（见下一节），逐一修复后，第 8 轮全程一致：

| 观察（第 8 轮） | 结果 |
|---|---|
| 问价 | 没有误买；铁匠按程序价格报价（第 6、7 轮里报的是"一金币八银币"） |
| 购买 | 长剑 1 金 8 银（自动装备）、药水 6 银，余 6 银，背包记录"购买：铁匠阿岩" |
| 开战 | 两只野狼（程序生成的 1 级敌人），先攻：艾琳 18 → 野狼2 12 → 野狼1 3 |
| 战斗 6 轮 | 第 1 轮移动 6 格还差一点没够到；之后命中、失手、大失手、两次暴击（12、17 点伤害）。叙述与结算一致（第 8 轮） |
| 结算 | 胜利，获得 100 经验，升到 2 级（生命上限 26），受了一处重创 |
| 制作 | 医疗检定 17 对难度 8 成功，消耗 2 株止血草，得到止血药膏（来源：制作） |
| 时间线校验 | 每轮都通过；退出后 llama-server 正常关闭 |
| 速度 | 每回合 14–28 秒（第一回合约 40 秒，包括模型预热）；敌人的行动不产生模型请求 |

### 联调中发现并修复的问题
1. **模型把买卖、开战、制作写成了效果类型**（第 1 轮）：例如 `{"type":"trade","seller":"N1","items":[...]}`，被校验拒绝，什么都没结算。现在程序会把它们移回正确的字段（兼容 seller / items / qty / recipe 等写法），提示词也写明这些不是效果。
2. **商人自己报价**（第 1 轮报"三十银"）：商人 NPC 的上下文里加入了程序定的价格。之后的报价与结算一致。
3. **买了剑却徒手作战**（第 2 轮）：模型没有写"装备"。现在拿到装备时对应栏位空着就自动装备；攻击时写明的武器会先换上；战斗中换装备立即生效。
4. **一个 GM 回合只移动一次就卡住**（第 2 轮）：目标太远时会在行动点允许的范围内一直靠近，进入射程后再攻击，然后结束回合。行动点剩 1 点时不会卡死。
5. **战斗原因显示成字段名**（例如"travel_to"）：现在用玩家的原话。
6. **主方案漏填字段**（第 3、4 轮：只在叙述里写"买下了"、商人留空）：
   - 新增补充识别：玩家明确提到买卖、物品、制作、动手而字段为空时，再发一个很小的请求，只让模型从编号里选；
   - 商人留空时，从在场商人里找卖这件东西的人；
   - "无"、难度 0 的检定不再掷骰。
7. **询价被当成购买**（第 5 轮，补充识别给出了数量 0 的购买）：补充识别只认明确的买卖动作，数量 0 视为没有决定。
8. **战斗中喝药恢复了 0 点又被用掉**（第 5 轮，程序问题）：
   - 原因：战斗中的生命在参战者身上，药水却按战斗外的方式作用在角色卡上。
   - 修正：战斗中的 `item_use` 转为战斗行动，战斗外的使用会拒绝正在战斗的人。
   - 已加回归测试。
9. **两个铁匠来打玩家**（第 6 轮，程序问题）：模型给"野狼"填了铁匠的编号。现在只有敌人名字确实指这个人物时才让他参战，并且只出现一次。
10. **"离我最近的那只野狼"找不到目标**（第 6 轮）：现在取名字被提到的敌人里最近的一个，都没提到就取最近的敌人。
11. **战斗中多出一次"武器检定"、战斗里写了 craft**：战斗中的攻击由程序掷骰，GM 另提的检定不掷；战斗中不制作；已经装备的武器不再重复装备。
12. 战场从 12×8 缩小到 10×6，近战第一回合能接近敌人；负数修正的显示从"+-1"改为"−1"。

## 已知问题和尚未完成的部分
1. **叙述偶尔与结算不符**：第 7 轮里，程序判定命中并击倒，叙述却写"没能触到"。提示词已经要求按结果叙述，第 8 轮一致，但无法保证每次都对。玩家可以在叙述下方看到程序的结算行。之后可以考虑程序侧检查（例如结算里有"倒下"而叙述没有提到）。
2. **模型仍会偶尔写出格式不对的效果**（例如 `check`、`any` 当效果类型），会被校验拒绝，不影响数据。
3. **敌人的行为比较简单**：只会靠近最近的对手并攻击，不会逃跑、包抄、使用物品；没有地形和掩体。
4. **战斗规则是通用的 d20 简化版**：没有法术位、职业、专长等系统化内容；可以通过自定义行动和规则设置扩展。
5. **同伴只能在战斗页手动加入**：GM 开战时不会自动带上在场的友好人物（方案里还没有"同伴"字段）。
6. **商店库存不会随时间补货**；物价不受世界模拟（战争、季节）影响。
7. **交易只有与商人的买卖**：还没有 NPC 之间的交易，也没有以物易物的界面。
